The flow

1

Your app starts a tunnel

The SDK opens a session with a PortalConfig — name, relays, what to serve. The native engine (libportaltunnel) handles the transport.

2

Relays connect you to the world

Portal relays are public servers that forward traffic. Your device registers with one or more relays and gets a public URL like https://name.portal.relay.com.

3

Visitors reach your device

Anyone with the URL can load your site, play your game, or hit your API. Traffic flows through the relay to your app — no server needed.

4

You stay in control

Stop the tunnel and the URL dies instantly. Rotate relays, update metadata, or hide from the directory — all live, no restart.

The path

The code

// Kotlin — one API, every platform
val client = PortalClient(context)
val tunnel = client.open(PortalConfig(
  name = "my-site",
  staticDir = siteDir,
  discovery = true
))
// → https://my-site.portal.relay.com

The same PortalClient API works on Android (JNI → libportaltunnel.so) and iOS (cinterop → libportaltunnel.a). One Kotlin Multiplatform library, one native engine, every platform.

Why Portal?

No infrastructure

No VPS, no domain, no DNS, no TLS certs. The relay handles the public endpoint.

Instant on/off

Start and stop programmatically. The URL lives only while your app runs.

Privacy options

ECH hides SNI from relays. MITM detection rejects intercepting relays. Hide from the directory for URL-only access.

Multi-relay

Connect to multiple relays for redundancy. URLs rotate as relays join and leave.
